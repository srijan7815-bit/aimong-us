# M1.5 — Native Android shell + the Commons (the AI cluster's home ground)

**Status: built and locally verified for the native shell; the cluster is live-tested
below. Reported 2026-11-01.**

The owner asked for two things that were not in PLAN.md:

1. the game must be played from a **native Android app** connected to the Render server,
2. the AI players must live on Render in a **persistent home** ("cluster") that the
   owner can **message as a group** and hand a **team code** to; the residents then
   walk into that match.

PLAN.md's M2 (movement & map) is untouched and still next — this work is numbered
**M1.5** so the locked milestone order does not shift (see `DECISIONS.md`).

## 1. Native Android app

| | |
|---|---|
| Where | `mobile/` (Capacitor 7 shell) — deliberately **outside** the pnpm workspace |
| App id / label | `us.aimong.app` / "AImong Us" |
| Bundle | `apps/client/dist` copied to `mobile/www`, compiled with `VITE_SERVER_URL=https://aimong-us.onrender.com` |
| Android | minSdk 23 (Android 6+), target/compile 35, `allowMixedContent: false`, cleartext off, INTERNET only |
| Output | `docs/app/aimong-us-0.1.2.apk` (~4.8 MB) |
| Rebuild | `bash scripts/build-apk.sh` (or the `android-apk` GitHub Actions workflow, which attaches the APK to every run) |

Why a WebView shell rather than a hand-written Kotlin client: PLAN §2 locks the client
to TypeScript + Phaser, and one codebase keeps the browser build and the APK
byte-identical apart from the server URL. What is native here is the **packaging**:
a real installed app, its own icon/splash, no address bar, no browser storage
eviction, and a bundled shell that opens without a network round-trip.

Branding is generated from the repo's own pod-bot vector —
`scripts/gen-android-assets.py` writes every launcher density, the adaptive icon,
9 splash sizes and the app label. No borrowed art.

### Verified

- `aapt dump badging`: `package: us.aimong.app`, versionCode 2, versionName 0.1.2,
  `application-label: 'AImong Us'`, targetSdk 35, INTERNET.
- Inside the APK: `assets/public/index.html`, `manifest.webmanifest`, `sw.js`,
  `icons/*` and the compiled bundle containing `https://aimong-us.onrender.com`.
- **Shell → Render round trip:** the exact `mobile/www` payload that ships in the
  APK was served from a fake origin (standing in for `https://localhost`) and
  driven headlessly as a phone: it booted, called `GET /healthz` and
  `POST /matchmake/create/game` on Render, created room `H6LG4`, and the server
  confirmed `H6LG4` with 1 player. Screenshot: `docs/shots/09-native-shell.png`.
- Not verified: the APK on physical hardware (no device in this environment) and
  a release build on Play Store (out of scope — the APK is sideloaded).

## 2. The Commons — the cluster's home ground

`apps/server/src/cluster/commons.ts`, rendered at **`/console`**.

- 12 residents are seated at boot from `config/personas.json` (identity) and
  `config/roster.json` (voice tier). They are server-side entities with statuses —
  `idle`, `invited`, `in-game` — not per-room spawn.
- **Message the house:** the owner broadcasts to all residents (or a subset over
  the API). Nothing is faked: with no LLM key configured the console says
  "no voice connected yet" and the feed shows a system line instead of inventing
  replies.
- **Team code:** the owner types a live room code, picks a seat count and an
  optional note; residents leave the Commons, are seated in that lobby as
  `isAi` players with their own names and colours, and are marked `in-game`. When
  the room closes they come home and the feed says so.
- Everything is in memory on the single Render instance (PLAN §4). The house
  sleeps with the free plan and is re-seated on boot; cross-game memory arrives at
  M6 and swaps the feed store for something durable.
- Owner auth: `CONSOLE_KEY` env var (constant-time compare; key is kept in the
  browser's localStorage, never in the page). If unset, the console works and
  warns in red that it is open — see `DECISIONS.md`.

## Test evidence

- `apps/server/test/cluster.test.ts` — 5 tests: seating from config, honest
  "no voice" behaviour, subset addressing, dispatch → in-game → home, last-dispatch
  record. `pnpm -r test` = **27 passing** (14 shared + 13 server).
- `apps/server/scripts/smoke.ts` extended to **17 checks** against a real server:
  commons snapshot with 12 residents, broadcast landing in the feed, 404 for a team
  code that has no live room, 3 residents seated in a live room as AI players,
  `in-game` marking, and everyone home again after the room disposes.
- Headless phone test (`docs/shots/10-…`–`12-…`): owner creates room `WHPK8` on a
  Pixel-7 viewport, console broadcasts a message, dispatches 4 residents, and the
  phone's lobby shows `Owner (HOST)`, `Mira`, `ro`, `kenji`, `zaraa` each badged
  **AI**, server-reported player count 5.

## Honest gaps

- Residents occupy seats and are visible; they do not **move, task, chat or decide**
  yet. That is M4 (scripted bodies) then M5 (LLM brain) — the seat layer is where
  both plug in.
- The APK is a debug-signed build (fine for sideloading, not for a store).
- Free Render plan sleeps after ~15 minutes idle; first open of the day takes
  30–60 s and the app's cold-start screen covers it.
